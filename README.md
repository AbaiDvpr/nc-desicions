# NC Decision

Рабочая папка для переписывания NC Consulting.

Два проекта лежат рядом. Это не один репозиторий с двумя пакетами: старый код — образец поведения, новый код — то, что мы пишем.

## Куда писать код

| Папка | Роль |
| --- | --- |
| `nc-dd-2023` | Старый проект. Читаем, чтобы понять, как уже работает продукт. Сюда новый код не пишем. |
| `NC-consulting-NEW` | Новый проект. Весь новый код только здесь. |

Задача: взять поведение из `nc-dd-2023` и заново реализовать его в `NC-consulting-NEW`. Стек, структуру файлов и имена классов не переносим один в один.

## Старый проект — `nc-dd-2023`

Laravel 10, PHP 8.1, Blade, Sanctum, PostgreSQL/MongoDB в зависимостях. Это действующая система: кабинет, финмодели, отчёты, учёт компании, админка, публичный сайт.

Куда смотреть, когда нужно понять старое поведение:

- финмодель и Excel-отчёты — `app/Components/Report`, `app/DataHandlers/Project`
- учёт компании (ДДС, ОПиУ, баланс) — `app/Components/Accounting`, `app/DataHandlers/Company`
- API кабинета — `routes/api.php`
- админка — `routes/backend`
- публичный сайт, регистрация, оплата — `routes/web.php`

`vendor/`, `storage/`, `node_modules/` не трогать и не использовать как образец архитектуры.

## Новый проект — `NC-consulting-NEW`

- `backend` — FastAPI, SQLAlchemy, PostgreSQL, JWT
- `frontend` — React, Vite, React Router

Сейчас в новом проекте уже есть вход, регистрация, профиль и финмодели (`/cabinet`, `/cabinet/models`). Дальше переносим остальные части старого продукта по одной, когда до них доходит очередь.

## Как переносить фичу

1. Найти в `nc-dd-2023`, что делает экран, формула или отчёт.
2. Понять вход, выход и правила расчёта.
3. Написать это заново в `NC-consulting-NEW`: API в `backend/app`, экран в `frontend/src`.
4. Старый PHP, Blade и Vue не копировать в новый проект.

Секреты (`.env`, ключи, пароли) из старого проекта в новый не переносить.
